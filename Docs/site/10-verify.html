What does the log prove?

On the session log as the artifact, and on where Braid stands.

The playground, step 7 · the braid command

Every answer leaves a log: one line per token, with every strand's numbers and hits. The log is the artifact, and braid verify replays it with no model loaded.

It checks that nobody edited the log: an answer's lines hash to the value its last line carries. It recomputes every share, every weight and every H_knn from the logged numbers. It replays the gate's memory token by token, which proves the ten-to-one clamp held. It replays every chain. And it re-reads every cited span from its source.

Every check passing is the expected result. The logs were written by Braid, and the checks are Braid's own, ported line for line. What the table shows is that the arithmetic is closed: a log is enough to recompute itself, and nothing outside it is needed to trust it.

Verified is not true

Verified means the cited text exists where the receipt says, and the arithmetic replays. It does not mean the answer is true.

On 2026-10-15 a Thread answered a question with another document's port number, pulled in through a sentence shape both documents shared, and that session verified. The receipt was honest about where the words came from. The words were wrong.

Where Braid stands

What moves the answer today. The gate is a memory of who has predicted better than the base model. It moves only while the prompt is read, and never by more than ten to one on any word.

The two entropies are written down at every word and replayed by braid verify. They move nothing yet: the module that reads them is switched off, because it did not beat the trace gate it was meant to replace. The trace is checked and never applied.

    Make it yours

    The playground is the shortest path to a Thread of your own. Change one thing at a time, run it, and read the receipt.

    • Your records. Edit the harbour log in Records.swift, or file your own app's values; an edited entry trains a new version on the next run.
    • Your question. Change the test prompt and its expected answer. A prompt in a record's own words, cut before the fact, shows the Thread best.
    • No training. .training(.off) indexes the pack's own blocks, and retrieval alone carries the facts.
    • More Threads. Add a ThreadRecipe from a folder, a dataset, or another app's records, and attach it.
    For model engineers: the log, the checks, the tolerances

    A session is JSONL, schema 1, one object per line with sorted keys: a header naming the strands and the gate's settings, then per generation a gen line, one tok line per position, and an end line with the touched partitions and the body's SHA-256. A tok line carries, per strand, the memory, w′, open, p_lm(y), p_knn(y), the share, H_lm, H_knn, the evidence, e_t, the shadow gate and share, up to 16 hits as [entry, score, value, row, offset, loss], and the chain state.

    braid verify's tolerances: shares sum to 1 within 1e-5; w′ within 1e-6; p and every share within 1e-5; H_knn within 1e-5; the memory within 1e-5. This site holds the memory to 1e-6. Exit 0 when everything replays, 3 when a span no longer matches its source, 65 when the log does not replay. --live re-reads spans from the AII lane as it stands now; --keys recomputes every cited key from a checkpoint.

    A log is about 2 KB per Thread per token, measured on 2026-10-15, against the plan's 2.5 KB at three Threads. It is self-contained, so verify needs no index.

    The log proves its own arithmetic and its own citations. Whether the answer is true is still the reader's call.
